# signals/0.4 — rationale

Successor to `signals/0.3.json`, locked 2026-10-08 in response to the project review (`docs/review-2026-10-08-project.md`). 0.1-0.3 stay on disk unchanged.

## What changed

| Proposal | Kind | Change | Why |
|---|---|---|---|
| P11 | TAG_DEPRECATION_PROPOSED | `BACKEND_EVALUATED.cost_objective_ref` → `objective_ref`; the perf category's boundary reads "optimization objective" | User decision 2026-10-08: "cost" refers to money only. The tag has never fired. |
| P12 | PAYLOAD_FIELD_PROPOSED | `capability_outcome` gains `not_established` | `native_process_tso` was recorded `absent` from an SDK header search; v0.2 §8.1 calls it open. A litmus run with no power would have recorded `present`. |
| P13 | PAYLOAD_FIELD_PROPOSED | `EXECUTION_STARTED.timeout_seconds`, `kill_grace_seconds`, `EXECUTION_COMPLETED.exit_code`, `elapsed_seconds` become optional; both tags gain optional `unobserved` | Imported runner executions carried `timeout_seconds=600.0`, `kill_grace_seconds=0.0`, `elapsed_seconds=0.0` as constants (TECHNIQUES.md #47). |

Notes changed without schema change: `GUEST_CALL_RETURNED` defines the `args_sha256` rendering (`Function(a1,a2)`, handles by role, integers in decimal), which the event probe already uses; T3 is not checked for executions that omit `timeout_seconds`.

## Compatibility

Guest tags are unchanged, so 0.4 ingests traces written under 0.1-0.4. On the harness plane P11 removes a required field from a tag that has never fired, and P13 only relaxes requirements, so every committed 0.3 record still validates except a `BACKEND_EVALUATED`, of which none exist.
