Successor to `signals/0.9.json`, locked 2026-10-24. 0.1 to 0.9 stay on disk unchanged.

How they were counted (2026-10-24): each of 0.9's 62 tags searched as a whole word in `src/`, `tools/`, `scripts/`,

tags occurs 1,080 times, every time in the JSON schema a record's baseline embeds or in Sprint 126's samples run, which
writes every harness kind on purpose; none fired from a code path. The 5 guest tags occur in none of `store/traces/`
(141 MB).

## What a deprecated tag means

- Its entry stays, with its payload, types and note, so every layer that names it (sessions, transitions, operators,
  evidence constraints) stays valid, and a record that carries it still reads and replays under its own baseline
  (TECHNIQUES.md #45: deprecation entries, not removals).
- Rust code gets no type for it: the generator leaves it out of `crates/events/src/generated.rs`, and out of
  `harness/schemas/harness-events.json`, so substrate refuses it on a new record. A guest-trace line with its tag is
  refused by name as deprecated, not as unknown.
- A hand-written Rust crate that names it fails `vocabulary_generator --check`.
- To fire one again, a sprint proposes it again (NEW_TAG_PROPOSED) with the code that emits it.

TRANSLATION_INVALIDATED and GUEST_FAULT_RAISED were the two the hardening review of 2026-10-17 asked to give emit
sites. Neither got one in Sprints 108 to 127. The host design of 2026-10-24 (change 3, invalidation) is where an
invalidation tag would fire; that sprint proposes it with its code.

## Which code speaks 0.10

Rust code: `signals/rust-current.json` names 0.10, and the Rust generator, the samples and the Signal Reports read
it. The frozen Python host speaks 0.9: `src/w2m/__init__.py` pins `VOCAB_VERSION = "0.9"`, and `scripts/gen_events.py`,
`scripts/check_records.py` and `tests/test_events.py` read `signals/current.json`, which keeps naming 0.9. No Python
file changes (Decisions 2026-10-23 user and 2026-10-24 agent-resolved). At step 4 of `docs/rust-port-plan-2026-10-24.md`,
when the Python host moves under `oracle/`, the two pointers become one.

## Compatibility

No tag, field, type or enum value is added or removed, and no stored record or trace carries a deprecated tag from a
code path, so 0.10 reads every record and trace written under 0.1 to 0.9: `guest_plane_compatible_versions` gains 0.10
and keeps 0.1 to 0.9. The Layer 10 override ("a change to any guest tag removes earlier versions from the list")
exists so that 0.10 never refuses a line an earlier version wrote; deprecating five guest tags that no trace holds
refuses none, so the earlier versions stay.
