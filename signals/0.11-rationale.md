## What each value means

- `exit_ns_p50`, `exit_ns_p99`: one VM exit's time, from `hv_vcpu_run` returning on the vCPU's exit to the vCPU's next
  `hv_vcpu_run`, in nanoseconds, the median and the 99th percentile over a run. `variant` names the exit kind
  (`hvc <k>` for a hypervisor call, or the exception class), as P20's `vm_exits` names it. The C monitor's exit alone
  measured 813 to 852 ns on 2026-10-24 (Sprint 132); the Rust host's one sample was 3,667 ns (Sprint 142).
- `runtime_word_hold_ns_p50`, `runtime_word_hold_ns_p99`: how long the runtime word (`RUN_TABLE + RUNTIME_LOCK`,
  `vm_backend.py` 518; 0 free, else its holder's vCPU index + 1) is held per taking, in nanoseconds. The host design
  (`docs/design-rust-host-2026-10-24.md`) assumes about 200 ns.
- `runtime_word_wait_ns_p50`, `runtime_word_wait_ns_p99`: how long a taker waits for the word before it holds it. The
  host design's revisit condition (Decision 2026-10-24) is a p99 wait over 10 µs.
- `wfe_exits`: the WFE or WFI traps (ESR's EC 0x01) a run took. 0 over a run whose guest executed a WFE says a guest
  WFE does not exit under Hypervisor.framework; a count says it does.

The quantiles follow `frame_time_ms_p50` and `frame_time_ms_p99`: a distribution as its quantiles, the dimension in
`variant` (Prometheus naming practice, as P19 and P20). Each value carries its unit in `unit` (`ns`, or `count` for
`wfe_exits`).
