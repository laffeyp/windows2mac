# signals/0.1 — rationale

Vocabulary Session for w2m, run 2026-10-05 per `sdd-kit-3/grammar/BOOTSTRAP.md`. Founding document: `windows_to_macos_research_direction_v0_2.md` (user decision, BLACKBOARD 2026-10-03). Output: `signals/0.1.json` (60 tags, 12 categories), `signals/proposals.json` (6 open, 1 rejected), and the gate `scripts/check_vocab.py`.

## Intent and scope

The vocabulary names what the w2m system can say about itself while it builds contracts, runs probes, compiles applications, and runs the product lifecycle. It replaces the lossy step v0.2 §11.3 names: "the generation system receives a structured discrepancy rather than an undifferentiated statement that a game failed." It covers both the harness's orchestration work and the guest program's observable effects. It does not encode Windows behavior; that is contract content under `contracts/`, with evidence.

The vocabulary fixes no game, backend, or graphics profile, because v0.2 §15 leaves all three open. Profiles appear as entities with enum-valued kinds; the two first application profiles (BioShock 2 Remastered, app 409720; The Blood of Dawnwalker, app 3751260) are instances recorded in BLACKBOARD, not vocabulary.

## Transport (Layer 6 decision taken first, because every layer depends on it)

Two planes share one vocabulary.

- **Harness plane.** Every non-guest tag is a substrate application event. Substrate takes the event kind from the Struct class name (`substrate/src/substrate/kernel/sequencer.py:177`, `event_kind = type(obj).__name__`) and validates the emitted Struct against the producer kind's declared schemas (`kernel/topology.py:185-205`). So each tag is a frozen msgspec Struct whose class name is the tag. The record's kind column and the vocabulary agree with no mapping table to drift. Cost: class names in UPPER_SNAKE break ruff's N801 naming rule in that one module; an inline exemption is cheaper than a mapping table.
- **Guest plane.** Guest effects are lines in a JSONL trace written by the profile under test. The Windows reference machine cannot import a Python emitter, and an application run can produce millions of lines, so guest lines never ride the bus. The `trace_ingester` operator validates every line (strict extras) and posts TRACE_INGESTED or TRACE_REJECTED with the trace's sha256.
- **Ordering.** v0.2 §11.4: "Recording evidence in one log does not serialize the game." Substrate `seq` orders orchestration only. Every guest line carries `thread_id`, `thread_seq`, and `hb_refs` (happens-before edges as `thread_id:thread_seq`). Guest order is that partial order and nothing else.

## Per-layer decisions

### Layer 0 — Ontology

22 entities, each cited to a v0.2 section in the JSON. Considered and folded:
- `EvidenceCategory` is an enum, not an entity: the three categories carry no state of their own.
- `Clause` was merged into `Contract`: v0.2 §11.2 versions whole contracts, and clause-level versions would double the revision machinery with no section asking for it (ENTITY_MERGE).
- `Shader` and `Pipeline` are not entities in 0.1: graphics artifacts are `Artifact` kinds until the first graphics profile (proposal P1).

`GuestAddress`, `CodeVersion`, `ClockValue`, and `HappensBeforeRef` are value objects.

Under-extraction check: every v0.2 subsystem in §2's diagram (evidence, contracts, application compiler, runtime services), §4 (distribution, bridge, bundle, backends), §8 (capabilities), and §13 (measurement) maps to at least one entity.

### Layer 1 — Lexical

60 tags. Form `{ENTITY}_{PAST_PARTICIPLE}`; irregular forms READ and BUILT are listed in the gate, and SESSION_INIT follows TECHNIQUES.md #9.

Chains are deliberate where a consumer acts differently at each point:
- COMPARISON_COMPLETED → REDUCTION_COMPLETED → DISCREPANCY_REPORTED → DISCREPANCY_ROUTED → DISCREPANCY_RESOLVED.
- Detection (comparison) and the §11.3 report are split because reduction takes many runner executions. The report must carry the *minimized* program.
- Routing is its own tag because the route decides which of two repair paths runs.

No ambient tags in 0.1: no measured cadence exists, and BOOTSTRAP Step 5 forbids an ambient tag without one (proposal P3).

Rejected:
- `GUEST_INSTRUCTION_EXECUTED`: per-instruction volume, and nothing in v0.2 asks to observe individual instructions outside memory and fault effects.
- `CONTRACT_DRAFTED`: CONTRACT_PROPOSED marks the only point a consumer acts on.

### Layer 2 — Payload

Every field is typed. 34 enums are declared once and referenced as `enum:<name>`, so a value set has one home.

Validator-extras posture: **strict** on both planes. A guest trace with an extra field fails ingest. Grounds: v0.2 §11.3 says a candidate must not change its expected output to pass. A lenient trace format would let a buggy runtime smuggle fields the comparator then ignores.

Semantic boundaries written into notes (the kit's `example/KIT_DIARY.md` lesson on `entry_count`):
- `accepted_count` sums three accept tags.
- `guest_line_count` is lines, not effects.
- `exit_status=faulted` is an observation, not a failure.
- `exhaustive=false` makes an out-of-set outcome inconclusive, not forbidden (v0.2 §9).
- `dropped_count > 0` bars exact and partial-order comparisons.

Foreign keys: 99 `_id`/`_ids` fields, 99 resolved to Layer-0 entities (gate output).

### Layer 3 — Session

Five strata: harness_run (parent), execution, model_check, guest_trace (linked by execution_id across transports), product_lifecycle (`framing_inferred`: v0.2 §12.1 names the steps but not a session concept). Persistent attributes appear only in open-tag payloads.

### Layer 4 — Temporal

Seven invariants. Two choices need defending:
- **T3 (execution window).** No global timeout constant exists. Each EXECUTION_STARTED carries `timeout_seconds` and `kill_grace_seconds`, because a litmus probe and a game launch differ by orders of magnitude, and v0.2 §3.1 makes timeouts observable behavior that normalization cannot erase.
- **T6.** The per-thread `thread_seq` rule is the only cadence on the guest plane, and it counts lines, not time.

### Layer 5 — State transitions

Fourteen rules. Three carry the v0.2 acceptance discipline:
- **S2.** Nothing is accepted under a replaced contract version.
- **S7.** The repair path taken must match the route.
- **S8.** An altered acceptance condition forces rejection.

S10 requires an evaluation of each backend before BACKEND_SELECTED, because v0.2 §8.2 keeps both as candidates.

Graph check: every session close is terminal (T2, S14). No cycles exist outside the product lifecycle's launch/exit loop, which is a named loop (relaunch). Every tag has an emitting operator (gate).

### Layer 6 — Runtime / Operator

16 operators, above BOOTSTRAP's 5–12 estimate. The split is required, not over-decomposition:
- `candidate_generator` and `acceptance_guard` are separate because v0.2 §11.2 says "the generator and checker have separate responsibilities."
- `reference_runner` and `destination_runner` are separate because they run on different machines.

Every operator names where it runs. Every model-routed operator (contract_builder, probe_author, candidate_generator) records `generator_ref` / `origin`, so a model-produced artifact can say it is one (PRINCIPLES.md runtime grammar).

### Layer 7 — Evidence

Thirteen constraints:
- **E4** keeps Windows on Arm out of native x86 evidence (v0.2 §11.1).
- **E5** requires a named published rule for every numerical envelope (v0.2 §10.2).
- **E10** keeps measurements out of acceptance (v0.2 §3.1).
- **E11** keeps Steam credentials out of every record. The security case: the Mac is logged into Steam, and the acquisition operator will handle login state.

All incident tags have diagnostic fields (E7) and all summary tags have outcome fields (E8); the gate enforces both.

## Project-specific overrides

- **Validator-extras posture:** strict, on both planes.
- **No view-payload-universal block in 0.1:** there is no view category yet (P2).
- **Enum values:** adding one bumps the minor version (Layer 10). A trace written with a new value fails ingest under the old version, so an added value is a compatibility event, not documentation.

## Agent-resolved decisions

Mirrored in `BLACKBOARD.md ## Decisions` (2026-10-05):

1. Tag name equals the substrate Struct class name (event kind); no mapping table.
2. Two transports: harness bus and content-addressed guest-trace files.
3. Guest order is (thread_id, thread_seq, hb_refs); substrate seq never orders guest effects.
4. Strict extras on both planes.
5. profile_kind includes `windows_arm_emulated` so such runs can be recorded, while constraint E4 bars them from native x86 evidence.
6. Graphics-specific tags deferred to P1/P2; graphics artifacts use artifact_kind until then.
7. No ambient tags in 0.1.
8. Discrepancy routing is deterministic on `reference_conforms`.
9. Execution timeouts are per-execution payload, not a global constant.
10. Hash format `sha256:<hex>`, identical to substrate's `content_hash`.

## Open proposals for v0.2

P1–P6 in `signals/proposals.json`: shader/pipeline tags, WINDOW_PRESENTED, FRAME_TIME_SAMPLED, GUEST_OBJECT_TRANSITIONED, GUEST_MODULE_LOADED / GUEST_CODE_MODIFIED, PROFILE_REGISTERED. P7 (clock monotonicity as a vocabulary invariant) is rejected: clock behavior is contract content with evidence.

## Defensibility spot-check (BOOTSTRAP Step 11)

Three tags picked at random from the 60, each with what this document says about it:

- **DISCREPANCY_ROUTED.** Why it exists separate from REPORTED: the route picks one of two repair paths, and S7 checks the path taken against the route; v0.2 §11.3 keeps the paths distinct. Boundary: deterministic on `reference_conforms`.
- **GUEST_CLOCK_READ.** Why one tag with a `clock` enum and not one tag per clock: the observation shape is identical, and the per-clock rules live in contracts (P7 rejected). Boundary: `tick_count` wraps at 2^32 ms.
- **ACCEPTANCE_CONDITION_ALTERED.** Why an incident rather than a CANDIDATE_REJECTED reason: it marks a breach of the v0.2 §11.3 rule, emitted by a separate operator, with both hashes as evidence; S8 forces the rejection.
