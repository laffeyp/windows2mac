## What each word means

- **`vcpus`**: the count of vCPUs the run was given. Absent means 1, so every record before 0.13, each made on one
  vCPU, keeps its meaning. The type is `u64`, which admits 0, and the generated schema's `ge` is 0. E14 states the
  lower bound, and it is enforced by type at the speaker's mouth: the next card's one emit site takes the count as
  `std::num::NonZeroU64`, which that card's scope carries.
- **`locked_model_steps`**: unit `count`, as `wfe_exits` is written. **`turn_start_ns_p50`** and
  **`turn_start_ns_p99`**: unit `ns`, as `exit_ns_p50` and `exit_ns_p99` are written. `unit` is `text`, and the
  vocabulary ties no metric to a unit. Both units are ones the Rust records already write (`run_measurements.rs`).
- **`holder`**: what the runtime word was held for when a `runtime_word_hold_ns_*` or `runtime_word_wait_ns_*` value is
  split by holder: a guest service, a host request, an in-VM or host compile and install, a turn's start, or a spin
  waiting for the word. `variant` keeps the site and the takings, as in 0.12. E15 (P29) holds `holder` to the four
  `runtime_word_*` metrics, and `crates/w2m_vm/src/bin/check_records.rs` checks it, as it checks T4's exemption for
  `guest_trace` false (Sprint 170); a holder left out, absent or null, is not checked. `turn_start_ns` is the turn's
  start from before its take of the runtime word to after its release, the wait included (`run.rs` 1367-1389); a
  `runtime_word_hold_ns` with `holder` `turn_start` is the hold alone.
- **`feat_lse2`**: whether the host reports FEAT_LSE2 (`hypervisor::feature("FEAT_LSE2")`, which `vcpus_allowed`
  reads before it admits a second vCPU). **`feat_bbm_level2`**: `present` when the FEAT_BBM level a vCPU reads in
  `ID_AA64MMFR2_EL1.BBM`, bits 55:52, is 2 or more, under which a change of block size alone needs no break (Sprint
  303), `absent` otherwise, the level read in `detail`. CAPABILITY_PROBED's outcome is `enum:capability_outcome`
  (`present`, `absent`, `error`, `not_established`), which cannot carry a level, so the capability is named for the
  property the design decides on (reviewer-4's tenth review, Medium 1). **`guest_wfe_exit`**: whether a guest WFE or WFI traps to the host (the WFE probe that
  `wfe_exits` counts).

## Who writes them

No code emits any of the new words yet; the next card does (`w2m-vm --vcpus N`'s record, CAPABILITY_PROBED where
`w2m-vm` makes its refusal checks). The two writers of EXECUTION_STARTED and MEASUREMENT_RECORDED today
(`crates/w2m_vm/src/record.rs`, for the batch run and `run_measurements`) set `vcpus` and `holder` to none. Both run
on one vCPU: the batch run takes the instruction clock, which `vcpus_allowed` holds to one vCPU, and `run_measurements`
passes no `--vcpus`. The samples run (`harness/vocabulary-samples.toml`) writes every new value through its Rust type.

## The proposal labels

P16, P17, P19, P20, P24, P26 and P28 are labelled ENUM_EXTENDED, and P14 and P15 TAG_PROPOSED, neither a kind of
`grammar/PRINCIPLES.md`'s eight. 0.13's `grammar_growth.project_overrides` declares ENUM_EXTENDED an alias of
PAYLOAD_FIELD_PROPOSED for an added enum value, and TAG_PROPOSED an alias of NEW_TAG_PROPOSED; the proposals keep their
labels, since `signals/proposals.json` is append-only (reviewer-4's tenth review, Low 3).

## The two pointers

`signals/rust-current.json` names 0.13. `signals/current.json` keeps naming 0.9, the frozen Python host's.
