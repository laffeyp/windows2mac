## scope

G3 judges w2m's batch run against 14 Windows runs: runner run 38216081440 and 13 laptop runs. A value the runs disagree
on passes as one Windows varies, so a value w2m shares with the runner's run alone passes, though the laptop is the
reference ("Match the reference", BLACKBOARD 160). Sprint 383 read 8 such values once, outside the tree: the time
zone's three (GetTimeZoneInformation's return at seq 921, two WideCharToMultiByte returns at 923-924) and the adapter
enumeration's five (EnumDisplayDevicesA(NULL, 1) at 1545, (NULL, 2) to (NULL, 5) at 1546-1549). The Decision "The
laptop's screen re-taken, and what G3's "conforms" still leaves" (Sprint 383's close) sets this card's two parts, one
concept: what w2m still answers as the runner where a stored laptop row answers otherwise.

- **The count, in code.** call_compare's verdict names each value Windows varies that w2m shares with runner runs alone
  and no laptop run (which run is which read from the stored runs, not by position), and counts them; G3's line in the
  gates quotes the count beside "conforms", and a test holds the count to a stored list, so a change in it fails until
  the list is regenerated with the change named. The count is no gate on its own: a value waiting on a probe stays
  listed with what it waits on.
- **The machine values with a laptop row** (Sprint 381's class search, `sprints/sprint-381-runner-values-left-re-taken.md`
  result, "machine values with a laptop row, not yet re-taken"), each family's laptop runs found by `probe.sha256`
  among `store/probe-runs/lap-20261013T231059422Z-136bec80-*`:
  - time_and_error_mode (`-180`, `-181`): the time zone, bias 480 "Pacific Standard Time" with its daylight rule,
    where w2m gives 0 "Coordinated Universal Time"; `local_time`. The game's three runner-only values move with it.
    GetTimeZoneInformation's return follows the date (the laptop runs of 2026-10-14 answer 2, daylight; those of
    2026-11-28 answer 1, standard): the answer is worked from w2m's clock by the zone's rule, and the rule's source
    named.
  - locale (`-116`, `-117`): `local.*`, `local.first_day` ret 0 err 87.
  - loader (`-112`, `-113`): `ldr.*_order`, the runners listing apphelp.dll where the laptop does not.
  - paths (`-132`, `-133`): `full.device_name` "x\\CON", the laptop "<cwd>\\x\\CON" where the runners "\\\\.\\CON".
  - file_attributes (`-076`, `-077`): `ex.dot` size_low 0 against 4096, `ex.file.trailing_backslash` err 267 against
    123.
  - process_parameters (`-136`, `-137`): `parent.standard_handles` input null, `parent.environment` version 3 against
    4, `parent.block` region 0x6000.
  Each family moves to a new contract version holding the laptop's rows through `store/family_runs/retaken-2026-11-27.tsv`,
  the old version byte-equal. A value whose laptop rows disagree between the family's two binaries, or between
  executions, is dropped by a named row rule, as `windows_laptop_rows` does.
- **The stream.** Each answer changed one at a time, each measured by one batch run against the stored stream; the
  stored stream regenerated by its rule; G3 on one and two vCPUs.
- **Not here.** The adapter enumeration (waiting on a laptop probe, which waits on the user's Smart App Control answer);
  the values Sprint 381 found settled by a Decision (processor topology, CPUID, audio) or varying by run. No Windows
  run; no API id added.
