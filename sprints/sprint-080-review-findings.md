## scope

The reviewer's large review of 2026-10-15 (no blocking defect; three high, four medium, two low findings) and its two
experiments: E1, a judge from spec-row random encodings (660,000 compiles, 0 differing, 89% with no stencil), and E2,

- **H2. The class identity holds the compiler.** `Rule.sha256` hashes the rule and its shared modules only;
  `vm_backend.py` (compile_insn, assemble_block) and `a64_encoder.py`, which every class verdict runs through, join it.
  Every class re-run on the committed tree.
- **M1. Guards by default.** Every value the samples never varied is guarded unless its class fixes it (the zero
  class); a hole whose samples fit two expressions that differ on a value of the same class is measured. E1 in CI
  (seeded, with the non-default NZCV contexts); a planted fault that disables the guards in the C fails it.
- **M2. canonical_flags pinned.** E2 in CI; `.get` on NZCV_CONDITIONS as compile_insn reads it.
- **M3. Clean stamps.** `record._changes` leaves out the run indexes a sweep writes (`store/runs/*.json`), so a
  family run started while another finishes stamps the tree it ran.
- **H3. Provenance.** The record committed in a form that does not depend on w2m's classes (bytes, address, flag
  arguments; gzip); the table committed in the same way; the two judge drivers under `scripts/`; the header stamped
  with the table's and the record's sha256; `gen_stencil_table.py --check` in CI.
- **L2.** A form's variants are unique by flag arguments (the generator asserts it); `vmc_emit` takes the first match.
- **M4, H1. Decisions.** Agent-resolved Decisions for refinement by a feature (076), canonical flag arguments and
  guards (079); and the departure from step 6's "generated from the rules": the table is inferred from compile_insn
  over keys a run reached, guarded, with its coverage measured in the VM before more is built on it.
