## scope

w2m answers display calls as GitHub's runner did: a 1024x768 screen with a work area to 720, at 96 DPI, on a Hyper-V
adapter. The laptop's screen is 1920x1080 with a work area to 1020, at an effective 120 DPI, on "Intel(R) UHD Graphics",
and its 13 reference game runs agree in every display return (Sprint 381's display table,
`sprints/sprint-381-runner-values-left-re-taken.md` result). The Decision "Which machine-decided values w2m answers as"
sets the display to the laptop's values. This card re-takes them, one concept: the laptop's screen as the programs see
it, from stored laptop rows (`WORKING_AGREEMENT.md` 301).

- **The values.** GetSystemMetrics at 120 DPI (the virtual screen 0x4c-0x4f, the screen size, caption 29, frame 4,
  the indexes the `display` family's laptop runs `lap-20261013T231059422Z-136bec80-034` and `-035` print), the
  monitor's rectangles and work area (GetMonitorInfoA/W, EnumDisplayMonitors), GetDpiForMonitor (effective 120, angular
  123, raw 141), EnumDisplaySettingsW's current mode and its mode list (66 modes at 144 and 60 Hz), the adapter and
  monitor strings of adapters 0-2; and the classes the values reach: `windows.c`'s work area and CW_USEDEFAULT
  placement (the `windows` family's laptop run `-192`: 160,160, not 78,78), and `dxgi` (`-036`, `-037`).
- **The families.** `display`, `windows` and `dxgi` held to 0.2.0 (or the next) contracts holding the laptop's rows,
  through `store/family_runs/retaken-2026-11-27.tsv`.
- **The stream.** The batch run's stored Rust stream regenerated by the rule Sprint 382 holds in code, the changed rows
  stated and measured; G3 conforms against the Windows runs on one and two vCPUs.
- **Not here: the adapter enumeration.** EnumDisplayDevicesA(NULL, 1) answers TRUE on the laptop (DISPLAY13) and FALSE
  in w2m; answering TRUE leads the game to indexes 2-5, and the contents of adapters 3 and 4 are in no stored row. The
  enumeration stays as it is, named as waiting on a laptop probe that asks for them, which waits on the user's Smart
  App Control answer. No API id is added.
