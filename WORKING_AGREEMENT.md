## Project identity

- **Project name:** w2m
- **Project type:** binary-translation toolchain + guest runtime + CLI; multi-language.
- **Project classes (TECHNIQUES.md §2):** CLI; game development (input replay, frame budget, determinism); visual (Metal output frames); audio; embedded-adjacent (guest runtime inside a VM).
- **Primary languages:** decided per component in Phase 1 and recorded here. Harness and probes: Python 3.12 (substrate's floor). Guest runtime: C, freestanding, compiled to AArch64 with clang (`--target=arm64-apple-macos14`, linked by `ld -preload` into an MH_PRELOAD image) and run inside the managed VM; Windows-visible state in guest memory at Windows layouts (Decision 2026-10-09, runtime architecture). Translator: Python on the host (`lift.py`, `vm_backend.py`) behind one block-translation interface.
- **Primary build commands:** `uv sync --all-extras`; `scripts/gates.sh` (all gates); the VM monitor builds itself (`clang`, `codesign` with `tools/vm_monitor/entitlements.plist`); the guest runtime builds itself (`clang --target=arm64-apple-macos14 -ffreestanding`, `ld -arch arm64 -preload`; `src/w2m/guest_runtime.py`); runner probes build on the runner (`clang`, `.github/workflows/windows-probe.yml`); the decode spec rebuilds from 0.6.3 with `scripts/rebuild_decode_spec.py`.
- **Adopted SDD kit version:** `sdd-kit-3` (2026-09-27).

## Project scope (verbatim from BLACKBOARD ## Decisions)

> Build the system described in `windows_to_macos_research_direction_v0_1.md`: obtain a Windows Steam game's distribution from the Mac command line, prepare it automatically, and launch it as a native Mac application; original Windows binaries are the input; Wine, Rosetta, and D3DMetal are not architectural dependencies. Use the substrate repo and the SDD kit.

The plan is `windows_to_macos_research_direction_v0_2.md` (user decision 2026-10-03). The CPU backend, first game, first graphics profile, and external shader-converter adoption are open; each is settled by a recorded decision with capability and conformance evidence (v0.2 §8.2, §15). Every test or qualification result names the profile it covers (v0.2 §12.1).

## External SDK bridge mappings

Written before any sprint authors code against the SDK (TECHNIQUES.md #46). Hypervisor.framework, Capstone and XED were used from Sprints 008, 014 and 017 without an entry here; the entries below were added 2026-10-08 (Sprint 027) after the project review found them missing.

- **substrate (`substrate.api`)** — source: substrate `docs/api.md` (read 2026-10-03). Surface in use: `TopologyBuilder.producer_kind / initial / trigger / route / view / termination / baseline`, `Runtime.run`, `read_record`, `assert_event`, `assert_no_event`, `assert_sequence`, `first_divergence`, `embedded_substrate`. Known gotchas from the docs: `finalised` does not mean succeeded (check `ProducerFailed`, `PredicateQuarantined`, or run `substrate run --strict`); predicates must call `.value()` on Views; `KindBuffer` is unbounded; `all_completed` hangs a resumed paused run; Level-3(b) replay is deferred.
- **Hypervisor.framework** — source: macOS 26 SDK headers in Xcode 26.6 (`Hypervisor/hv_vm.h`, `hv_vcpu.h`, `hv_vm_config.h`, `hv_sys_reg.h`), read for Sprint 008. Surface in use: `hv_vm_config_create`, `hv_vm_config_set_ipa_granule(HV_IPA_GRANULE_4KB)` (macOS 26), `hv_vm_create`, `hv_vm_map`, `hv_vcpu_create`, `hv_vcpu_run`, `hv_vcpu_get_exit_info`, `hv_vcpu_set_reg`/`get_reg`, `hv_vcpu_set_sys_reg(HV_SYS_REG_ACTLR_EL1, 1 << 1)` (EnTSO, macOS 15). Gotchas found: the process needs the `com.apple.security.hypervisor` entitlement (`probes/mac_hv_capability/entitlements.plist`); the default IPA granule is 16 KB and refuses a 4 KB map (HV_BAD_ARGUMENT); with the guest MMU off, data accesses are Device memory and ordering looks strong regardless of EnTSO, so litmus runs need stage-1 tables with Normal WB memory; one `hv_vcpu_t` per host thread.
- **Hypervisor.framework, Sprint 030 additions** — source: the same SDK headers (`hv_vcpu.h`, `hv_vcpu_types.h`), read before `tools/vm_monitor/vm_monitor.c` was written. Surface added: `hv_vcpus_exit` (callable from any thread; the monitor's watchdog uses it), `HV_EXIT_REASON_CANCELED`, `HV_SYS_REG_{SCTLR,TTBR0,TCR,MAIR,VBAR,ESR,FAR,ELR}_EL1` (ids 0xc080, 0xc100, 0xc102, 0xc510, 0xc600, 0xc290, 0xc300, 0xc201), `HV_REG_X0`..`HV_REG_X30` contiguous. Measured before relying on it: after an HVC exit the vCPU PC is the address after the `hvc`; a file-backed `MAP_SHARED` mapping is accepted by `hv_vm_map`, so host and monitor share guest memory without copying.
- **A64 instruction encodings** — source: Arm ARM (DDI 0487) section C6. Checked, not trusted: every form `src/w2m/a64_encoder.py` emits is assembled by clang (`--target=aarch64-linux-gnu`) in `tests/test_a64_encoder.py` and must produce the same word.
- **Metal / Metal Shader Converter** — pending; `metal-shaderconverter` is not installed on this host.
- **DepotDownloader** — not adopted (2026-10-09). It is a third-party client of a reverse-engineered Steam protocol that needs the account password; Valve's own SteamCMD does the same job. A Homebrew tap of it was trusted and partly installed without the user's approval on 2026-10-09 and then removed (`brew uninstall`, `brew untap`, `brew untrust`).
- **SteamCMD** (Valve) — source: Valve Developer Wiki, "SteamCMD" (search-result excerpts, 2026-10-09; the page itself sits behind a bot check); the macOS bootstrap `steamcdn-a.akamaihd.net/client/installer/steamcmd_osx.tar.gz` (HTTP 200, 2,523,751 bytes, 2026-10-09), installed at `~/w2m-tools/steamcmd`, self-updated to version 1788292693. Surface in use: `+@sSteamCmdForcePlatformType windows`, `+force_install_dir`, `+login <user>` (interactive password and Steam Guard, run by the user), `+login anonymous`, `+app_info_update 1`, `+app_info_print <app>`, `+app_update <app> validate`, `+quit`. Output: `<dir>/steamapps/appmanifest_<app>.acf` with build id and depot manifest ids.
- **zstd 1.5.7** (Homebrew on the Mac; on the runner `zstd --version`, else `choco install zstandard`) — surface: `zstd -T0 -6 -q -c` (pack), `zstd -d -c` (unpack). Parts split at 1,900 MiB, under GitHub's 2 GiB release-asset limit (GitHub Docs, "About releases").
- **Mono embedding API (Unity's fork, `unity-2019.4-mbe`)** — source: Unity-Technologies/mono at that branch, `mono/metadata/profiler.c`, `profiler.h`, `profiler-events.h`, `mono/mini/mini-runtime.c`, read 2026-10-09; every symbol checked present in the game's `mono-2.0-bdwgc.dll` by its strings. Surface in use (`tools/jit_capture/jit_capture.c`): `mono_profiler_create`, `mono_profiler_set_jit_done_callback` (MonoProfiler *, MonoMethod *, MonoJitInfo *), `mono_profiler_set_jit_code_buffer_callback` (buffer, size, MonoProfilerCodeBufferType, data), `mono_jit_info_get_code_start`, `mono_jit_info_get_code_size`, `mono_method_full_name`, `mono_method_get_class`, `mono_class_get_image`, `mono_image_get_name`, `mono_free`. Not available: `--jitmap` (compiled under `ENABLE_JIT_MAP`; its format string is absent from this build).
- **Unity player (2019.4.40f1)** — sources: Unity Manual 2019.4, "Player command line arguments" (official documentation, read 2026-10-09); `Hail to the Rainbow.exe` disassembled (its entry is one `jmp` through the IAT to `UnityPlayer.dll!UnityMain`). Surface in use: `UnityMain(HINSTANCE, HINSTANCE, LPWSTR, int)` called with wWinMain's arguments; `-batchmode`, `-nographics`, `-logFile <path>`; the data folder is found by the executable's name (`<exe>_Data`).
- **Capstone 5.0.9 (Python)** — source: capstone PyPI package and `capstone/__init__.py`, `x86_const.py`, read for Sprint 014. Surface in use: `Cs(CS_ARCH_X86, CS_MODE_64)`, `.detail = True`, `disasm(raw, address, count=1)`, `insn.groups` (`X86_GRP_JUMP`, `X86_GRP_CALL`), `insn.operands` (`X86_OP_IMM`, `X86_OP_MEM` with `mem.base == X86_REG_RIP`). Gotchas: no type stubs (mypy override in `pyproject.toml`); Woodruff et al. (LangSec 2021) measured Capstone as unreliable on unusual encodings, so it is a voter, not a judge (Decision 2026-10-08).
- **Intel XED v2026.08.23** — source: `third_party/xed` at commit 0bcb6237345c (`xed-interface.h`, `xed-decoded-inst-api.h`, `examples/`), read for Sprints 017 and 022. Surface in use (`tools/xedshim/xedshim.c`): `xed_tables_init`, `xed_decoded_inst_zero`, `set_mode(XED_MACHINE_MODE_LONG_64, XED_ADDRESS_WIDTH_64b)`, `set_input_chip`, `xed_decode`, `xed_format_context(XED_SYNTAX_INTEL)`, iclass/iform/length getters, operand walk via `xed_decoded_inst_inst`, `xed_inst_operand`, `xed_operand_operand_visibility`, register, memory, immediate and branch-displacement getters. Gotchas: without a chip, XED decodes for an older CPU (BSF for F3 0F BC; NOP for F3 0F 1E FA), so the shim sets a chip (ALL by default); mbuild looks for `llvm-ar` on macOS (`--ar=$(xcrun --find ar)`).

## Sprint cadence policy

- **Observation contracts state an outcome (2026-10-09, review progress K4):** a bound, an expected value, or a planted fault the check must catch. "Whatever the record shows" is not an observation contract.
- **Hard rule 6 override (2026-10-09, BLACKBOARD Decision; settles KIT_DIARY H3):** a sprint holds one concept, one observation contract and one verdict. Its file count is recorded, not capped; a card over 10 files names why it is not two sprints. Two failed attempts at a sprint over 10 files split it.
- **Phase 0 (Vocabulary Session):** `signals/0.1.json` + rationale covering evidence, contracts, probes, code validity, discrepancies, repair vs revision, backends, artifacts, and the product lifecycle (v0.2 §3, §5.1, §11, §12, §14).
- **Phase 1 (Contract construction and harness):** the contract format with evidence categories (v0.2 §11.1-11.2); substrate topologies for probe, model check, candidate, comparison, and reduction (§11.4); first probes on the Windows reference profile.
- **Phase 2 (Destination capability probes):** both backend candidates probed on this host: VM 4 KB IPA granule and guest TSOEN (OQ-1); native-process page enforcement and the execution time of ordering variants. Output: capability-profile evidence, not a backend choice (§8.2).
- **Phase 3 (Application profile and product slice):** first game chosen (user-only Q1); its profile drives contract coverage; the product slice covers acquisition, Steam session, run, state, close, relaunch, update, removal (§12.1).

- **Decoder phase (Sprints 013-023, inside Phase 3):** PE reader, reference traversal, spec-generated decoder, differentials against XED. Exit criteria (Decision 2026-10-08):
  - (a) generated differential: `length_differs` 0, and the decoder raises nothing but `DecodeError` and its subclasses on any input (met, Sprint 023);
  - (b) corpus and probe binaries: length and iclass equal XED's at every reachable position; spec gaps 0 (met, Sprint 023);
  - (c) the faults XED reports for a legacy prefix or REX before VEX/EVEX/XOP, for length over 15, and for truncated input are refused as `InvalidEncoding` or `Truncated` (met, Sprint 023);
  - (d) every spec row that the chosen game's reachable code uses is XED-confirmed in `specs/x86_decode_confirmations.json` (met, Sprint 036: 718 of 718 rows, spec 0.7.0; exception: 2 APX positions no target CPU executes). Re-pointed 2026-10-09 (review 2026-10-09 H4) at the x86-64 profile, Hail to the Rainbow: its reachable code is the Capstone traversal of its seven native PE files plus the code Mono generated on the runner (`scripts/game_code_differential.py`). First measurement (Sprint 033, spec 0.6.3): 577 rows used, 142 not confirmed; 8,935 positions in 123 kinds have no row. Criterion (b)'s "spec gaps 0" held on the Python corpus and does not hold on this game. Sprint 036: 0 positions without a row except those 2.

## Custom techniques

- **Oracle-first contract mining** (amended 2026-10-08 to match the 2026-10-07 user decision that reference runs are optional). A contract clause enters `contracts/` with documented or observed evidence; a hypothesis alone cannot carry acceptance (`src/w2m/contract.py`). Observed evidence names its executions (`execution_ids`, resolved against `store/`). Success: every accepted clause cites a quoted document or a stored execution. The original wording required an oracle run for every clause.
