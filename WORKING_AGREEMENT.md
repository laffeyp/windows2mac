## Project identity

- **Project name:** w2m
- **Project type:** binary-translation toolchain + guest runtime + CLI; multi-language.
- **Project classes (TECHNIQUES.md §2):** CLI; game development (input replay, frame budget, determinism); visual (Metal output frames); audio; embedded-adjacent (guest runtime inside a VM).
- **Primary languages:** from 2026-10-21, Rust, and Rust only, for every part of w2m: host, translator, judges, checks and tools (user Decisions 2026-10-21 and 2026-10-23; `docs/rust-port-plan-2026-10-21.md`). Python runs only as substrate, the harness (user 2026-10-22), reached through substrate's language-neutral process producer and topology file (Decision 2026-10-23, Sprint 125), and as the frozen oracle at `python-final`. What follows is the state before the port, until each part is replaced: harness and probes: Python 3.12 (substrate's floor). Guest runtime: C, freestanding, compiled to AArch64 with clang (`--target=arm64-apple-macos14`, linked by `ld -preload` into an MH_PRELOAD image) and run inside the managed VM; Windows-visible state in guest memory at Windows layouts (Decision 2026-10-09, runtime architecture). Translator: Python on the host (`lift.py`, `vm_backend.py`) behind one block-translation interface.
- **Primary build commands:** `uv sync --all-extras`; `scripts/gates.sh` (all gates); the VM monitor builds itself (`clang`, `codesign` with `tools/vm_monitor/entitlements.plist`); the guest runtime builds itself (`clang --target=arm64-apple-macos14 -ffreestanding`, `ld -arch arm64 -preload`; `src/w2m/guest_runtime.py`); runner probes build on the runner (`clang`, `.github/workflows/windows-probe.yml`); the decode spec rebuilds from 0.6.3 with `scripts/rebuild_decode_spec.py`.
- **Adopted SDD kit version:** `sdd-kit-3` (2026-09-27).

## Project scope (verbatim from BLACKBOARD ## Decisions)

> Build the system described in `windows_to_macos_research_direction_v0_1.md`: obtain a Windows Steam game's distribution from the Mac command line, prepare it automatically, and launch it as a native Mac application; original Windows binaries are the input; Wine, Rosetta, and D3DMetal are not architectural dependencies. Use the substrate repo and the SDD kit.

The plan is `windows_to_macos_research_direction_v0_2.md` (user decision 2026-10-03). The CPU backend, first game, first graphics profile, and external shader-converter adoption are open; each is settled by a recorded decision with capability and conformance evidence (v0.2 §8.2, §15). Every test or qualification result names the profile it covers (v0.2 §12.1).

## External SDK bridge mappings

Written before any sprint authors code against the SDK (TECHNIQUES.md #46). Hypervisor.framework, Capstone and XED were used from Sprints 008, 014 and 017 without an entry here; the entries below were added 2026-10-08 (Sprint 027) after the project review found them missing.

- **substrate (`substrate.api`)** — source: substrate `docs/api.md` (read 2026-10-03). Surface in use: `TopologyBuilder.producer_kind / initial / trigger / route / view / termination / baseline`, `Runtime.run`, `read_record`, `assert_event`, `assert_no_event`, `assert_sequence`, `first_divergence`, `embedded_substrate`. Known gotchas from the docs: `finalised` does not mean succeeded (check `ProducerFailed`, `PredicateQuarantined`, or run `substrate run --strict`); predicates must call `.value()` on Views; `KindBuffer` is unbounded; `all_completed` hangs a resumed paused run; Level-3(b) replay is deferred. From Sprint 125 (substrate card 270, `docs/process-producer.md`, read 2026-10-23), the surface the Rust w2m uses: `substrate run --file` with a TOML topology, process Producers that write one `{"kind", "payload"}` JSON line an event to standard output and read their input as one JSON line on standard input, and schema files (`schema_version`, kinds, fields with `type` or `enum`, `pattern`, `min_length`, `ge`, `le`, `optional`); `substrate tail --format jsonl` and `substrate replay --level 2` to read and check a record. Gotchas: an optional field left out is null on the record; a bad line ends the Producer as `substrate.ProducerFailed` naming the line, and `run` exits 0 unless `--strict`; the import layers put the process Producer in `substrate.app`, not `substrate.api`.
- **Hypervisor.framework** — source: macOS 26 SDK headers in Xcode 26.6 (`Hypervisor/hv_vm.h`, `hv_vcpu.h`, `hv_vm_config.h`, `hv_sys_reg.h`), read for Sprint 008. Surface in use: `hv_vm_config_create`, `hv_vm_config_set_ipa_granule(HV_IPA_GRANULE_4KB)` (macOS 26), `hv_vm_create`, `hv_vm_map`, `hv_vcpu_create`, `hv_vcpu_run`, `hv_vcpu_get_exit_info`, `hv_vcpu_set_reg`/`get_reg`, `hv_vcpu_set_sys_reg(HV_SYS_REG_ACTLR_EL1, 1 << 1)` (EnTSO, macOS 15). Gotchas found: the process needs the `com.apple.security.hypervisor` entitlement (`probes/mac_hv_capability/entitlements.plist`); the default IPA granule is 16 KB and refuses a 4 KB map (HV_BAD_ARGUMENT); with the guest MMU off, data accesses are Device memory and ordering looks strong regardless of EnTSO, so litmus runs need stage-1 tables with Normal WB memory; one `hv_vcpu_t` per host thread.
- **Hypervisor.framework, Sprint 030 additions** — source: the same SDK headers (`hv_vcpu.h`, `hv_vcpu_types.h`), read before `tools/vm_monitor/vm_monitor.c` was written. Surface added: `hv_vcpus_exit` (callable from any thread; the monitor's watchdog uses it), `HV_EXIT_REASON_CANCELED`, `HV_SYS_REG_{SCTLR,TTBR0,TCR,MAIR,VBAR,ESR,FAR,ELR}_EL1` (ids 0xc080, 0xc100, 0xc102, 0xc510, 0xc600, 0xc290, 0xc300, 0xc201), `HV_REG_X0`..`HV_REG_X30` contiguous. Measured before relying on it: after an HVC exit the vCPU PC is the address after the `hvc`; a file-backed `MAP_SHARED` mapping is accepted by `hv_vm_map`, so host and monitor share guest memory without copying.
- **Hypervisor.framework, the surface for the Rust bindings** (2026-10-22, before any Rust is written; Decision 2026-10-22) — source: the installed SDK's `Hypervisor.framework/Headers` (`hv_vm.h`, `hv_vm_config.h`, `hv_vcpu.h`, `hv_gic.h`, `hv_gic_config.h`). `tools/vm_monitor/vm_monitor.c` calls 26 functions; the entries above name 10 of them. The other 16: `hv_vcpu_get_sys_reg`, `hv_vm_config_set_ipa_size`, `hv_vm_destroy`, `hv_vcpu_destroy`, `hv_vcpu_get_simd_fp_reg`, `hv_vcpu_set_simd_fp_reg`, `hv_vcpu_set_vtimer_mask`, and nine GIC calls, `hv_gic_config_create`, `hv_gic_config_set_distributor_base`, `hv_gic_config_set_redistributor_base`, `hv_gic_create` (hv_gic.h: only after the VM is created), `hv_gic_get_distributor_size`, `hv_gic_get_distributor_base_alignment`, `hv_gic_get_redistributor_base_alignment`, `hv_gic_get_redistributor_region_size`, `hv_gic_get_redistributor_base`. Each binding's signature is copied from its header declaration, and the binding sprint's card quotes them; none is written from memory. **Bound in Rust (Sprint 132, `crates/hypervisor`), from the macOS 26.5 SDK:** `hv_vm_config_create`, `hv_vm_config_set_ipa_size`, `hv_vm_config_set_ipa_granule`, `hv_vm_create`, `hv_vm_destroy`, `hv_vm_map`, `hv_vm_unmap`, `hv_vcpu_create`, `hv_vcpu_destroy`, `hv_vcpu_run`, `hv_vcpus_exit`, `hv_vcpu_get_reg`, `hv_vcpu_set_reg`, `hv_vcpu_get_sys_reg`, `hv_vcpu_set_sys_reg`, `hv_vcpu_set_vtimer_mask`, and `os_release` for the config. ## Sprint cadence policy

- **Observation contracts state an outcome (2026-10-09, review progress K4):** a bound, an expected value, or a planted fault the check must catch. "Whatever the record shows" is not an observation contract.
- **A planted fault names its reach (2026-10-09, KIT_DIARY #21, #22):** the card states the fault, the field it changes, and how many reference cases change that field, counted before the card is executed. A plant with no reference case that shows it is a blind spot, recorded as such, never a test. A reference generator's inputs are frozen per run and must not depend on the code it judges (#23).
- **Hard rule 6 override (2026-10-09, BLACKBOARD Decision; settles KIT_DIARY H3):** a sprint holds one concept, one observation contract and one verdict.
