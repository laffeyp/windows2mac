360 review, 2026-10-17: code, SDD, Substrate, and A Philosophy of Software Design

The code is checked strictly, but it was built tactically, which is the failure Ousterhout names first. In ten days, 102 sprints each added to the nearest file. Nobody redesigned the structure when the project's direction changed: twice, at the recentering and at the pivot to Microsoft's DLLs. The judges are excellent and the design under them is not. The pivot is the right moment to fix that, because it hands w2m the deepest interface the project could have, the NT system-call table. No code for it exists yet: tools/guest_runtime/ still holds 51 files and 9,300 lines of per-API services, and none of them handles a system call.

1. Against A Philosophy of Software Design (Ousterhout, 2nd ed., 2021)

Modules should be deep (ch. 4). src/w2m/vm_backend.py is 4,813 lines.
- The class: VM alone is 2,577 lines, with 129 methods and 93 instance attributes.
- What the one file holds: an assembler, the flag lowerings, the compiler (compile_insn, a single 469-line function) and the transport (Channel). It also holds the page tables, the loader data, thread creation and switching, the host requests, the code cache, the run loop (steps, 279 lines), and the diagnostics (lockstep, state_differential).
- The interface: of its 47 public methods, about 20 are paired getters and setters over guest state: af/set_af_df, x87/set_x87, mxcsr/set_mxcsr, vectors/set_vectors, ymm_hi/set_ymm_hi. That is a shallow interface, and the guest state's layout leaks to every caller (ch. 5).
- The leak, measured: tests call private names 29 times, and tests/test_vm_compiler_c.py alone reaches into vm_backend 25 times.

Hard rule 6 (two files or fewer, one concept) is kept only in form. Most commits touch one to six code files, because one of those files holds everything.

Change amplification (ch. 2). One x86 instruction's meaning now lives in up to seven forms:
- rules/ and lift.py;
- the Python model (runtime.py, 1,191 lines, plus integer_model.py, x87.py and x86fp.py);
- compile_insn;
- the captured stencils (store/stencil/table.txt.gz);
- the generated tools/vm_compiler/stencil_table.h, 91,611 lines and committed;
- the C compilers, vm_compiler.c and block_compiler.c;
- symbolic_lift.py and symbolic_compile.py.

The uncommitted working tree shows the cost: a 4-line change to lift.py rewrites 138,136 lines of stencil_table.h. Fixes:
- One source, the rules, should generate one compiler.
- stencil_table.h should be a build product checked by hash, not a committed file.
- The symbolic line (Sprints 089 and 090) should go, since Sprint 090 itself measured that its forks multiply.

Different layer, different abstraction (ch. 7), and design it twice (ch. 11). The pivot names the layers, and the code should follow them:

| Layer | Content |
|---|---|
| cpu | decoder, compiler, code cache |
| memory | page tables, guest view |
| nt | objects, threads, waits; one entry, syscall(number, args), over the 488 numbers |
| host | channel, clock, window, files |
| diagnostics | lockstep, state differential |

The new kernel should be built as the nt module from its first line, not grown inside VM. Its interface is the deep one: 488 numbers behind a single entry, with all of Microsoft's user mode above it. Two designs should be sketched before the first syscall handler is written, as Ousterhout asks. The one to compare against is Wine's split, a server that owns the objects with a client-side ntdll.

Comments say what the code cannot (ch. 12-13).
- Sprint numbers: source and C carry 749 "Sprint NNN" references. That is history, and history belongs in git.
- A stale docstring: vm_backend.py's docstring still calls the file vm.py, says it holds "kernel32", and describes one vCPU.
- The fix: comments should hold the invariants (the register map, the exit codes, the commit rule), and the sprint provenance should move to commit messages.

Temporal decomposition and hidden layers (ch. 5, 9).
- scripts/ is a library in disguise. Scripts and tests import one another 85 times through mypy's mypy_path = "scripts:tests". family_run.py, at 3,267 lines, is imported by 11 files, and stencil_census by 6.
- Code that others import belongs in src/w2m, and a script should be a thin main.

Working code is not enough (ch. 3). Ousterhout puts strategic investment at 10 to 20% of the effort. None of 053 to 102 was a design sprint. Sprints 101 (a vocabulary bump) and 102 (the laptop's initial state) took the slot where several vCPUs belonged, which was roadmap step 3.

What the project does right, on this book's own terms.
- Design for performance (ch. 20). Speed work is measured first and judged on the critical path. Sprint 094 timed 100 billion instructions in 44.3 to 48.7 s, an fps-equivalent of 50 to 55. It also showed that the main thread's 233.6 million PAUSEs are counted in that rate.
- One source for the layout. The 63 W2M_* layout constants reach the C runtime through -D defines from one Python table.
- Generators checked. Generated code is checked with --check in the gates.

2. SDD adherence (sdd-kit-3/AGENTS.md)

1. The vocabulary is partly fiction (hard rule 2). 24 of the 62 tags in 0.8 are never referenced outside the generated events.py. Some are aspirational: the APPLICATION_* tags and STEAM_SESSION_*. Two are worse, because the events they name happen and go unrecorded:
   - TRANSLATION_INVALIDATED: Mono rewrites code, and code_rewrite has a plant;
   - GUEST_FAULT_RAISED: the frontier counts dispatched faults and prints the count to stderr.

   Those two should be emitted, and the never-emitted ones retired through a typed proposal.
2. The Rubber Duck Pass has nothing to read.
   - What the record holds: a 100-billion-instruction frontier run records about five producers' events.
   - What it leaves out: the numbers that decide the work, namely exits by hvc, host seconds, the PAUSE count, the wake census, the thread census

  - gates.sh under set -eu, with the Substrate commit pinned and checked;
  - CI on every close.
- Suppressions: 144 noqa and 27 type: ignore in src and scripts. Many of those noqa marks are BLE001, on 18 broad except clauses. Ousterhout's chapter 10, "define errors out of existence", is the test for each: most should name the exception they expect.
- Python on the hot path: _slow_sse still runs the Python model inside the VM's run (vm_backend.py:3706). Host requests (hvc 8) cost 4.4 to 7.2 s per 100 billion instructions.

5. What to do, in order

1. Several vCPUs now (roadmap step 3, skipped for Sprints 101 and 102), with the litmus tests as the gate.
2. The nt module as a new deep module, sketched twice against Wine's split, with one entry over E1's 73 kinds of system call. It is not to be grown inside VM.
3. Split vm_backend.py along the five layers as the nt module lands, with the diagnostics moved out first, since they are the cheapest cut.
4. One semantics source and one generated compiler. The symbolic line goes, and stencil_table.h leaves git.
5. Measurements as signals. Emit TRANSLATION_INVALIDATED and GUEST_FAULT_RAISED, and retire the other 22 unemitted tags.
6. Substrate made real or named as a record store.
7. The registry rewritten, with the sprint history taken out of comments.
8. A user decision on deleting superseded code.
